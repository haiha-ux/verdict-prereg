# Amendment 15 (append-only) — 20 independent site-split replicates (design and lock, 2026-10-28, BEFORE any replicate was run)
Reason: the independent critic of Amendment 14d found that C3/C4 rest on one fold assignment and one audit pool per set. This amendment adds a robustness run with R = 20 independent re-draws of the site-to-fold and audit/eval assignment (seed [20261028, 77, r, set]) over the SAME sampled frames and features (no new image, no new feature). Code: experiments/ct_rep.py (calls the locked ct_run functions unchanged; hash in locks.txt).
Per replicate and set: C1 P0 regrets of R0/Q/Otsu, error of R0 and oracle, constant 'animal' error 1 - mean(label), AUC; C2 mean(Q - R0) in fold-pools PH/PL with |prior shift| >= .20 (with the number of such pools and which sets); C3 covered / n over cases (fold x pool x {R0, Q}) overall and in shifted pools; C4 betting-bound and frame-level Clopper-Pearson coverage of the pooled R0 error for k in {5, 10, 20} audit sites (2000 subsamples of the replicate's audit pool).
Pre-stated reading: C4 coverage is judged ACROSS replicates (mean over the 20 replicates; share of replicates with coverage < .95), not within one pool. A claim 'coverage >= .95' is allowed only if >= 19 of 20 replicates meet it for that set and k. C3 is reported as counts with the shifted/unshifted split; no pass/fail threshold. C2 is reported as the distribution over replicates, with the number of replicates in which any CCT or Wellington pool is shifted. No Holm. No claim that Q or the certificate 'works'. The set of replicates is not extended after seeing results; a replicate that crashes is reported.
Expected (stated before the run): CP undercovers at k = 5 and 10 in at least one set; betting stays >= .95; C2 positive only in Serengeti.
Tier-1 is not affected by this run (3 datasets, WCS unconfirmed, PX not run).

## Addendum 15b (2026-10-28): result of the single locked replicate run (result_rep.json SHA-256 d877d778482c6b909f5733247bb776bfc3176e7e33778c89be4db036a2c34145; summary: experiments/out/camtrap/rep_summary.txt). Independent critic pending at the time of writing.
Run once, 20 replicates, none crashed, after the lock at 13:00:43Z.
C4 (cluster audit): the betting bound covered the pooled R0 error with coverage 1.0 in every replicate for every set and k in {5, 10, 20} (0 of 20 replicates below .95); median upper bound / truth: CCT 4.7 / 3.2 / 2.3, Wellington 3.5 / 2.5 / 1.9, Serengeti 9.6 / 6.3 / 3.9 (k = 5 / 10 / 20): valid but loose. Frame-level Clopper-Pearson coverage averaged .67-.89 and was below .95 in 12-20 of 20 replicates per set and k (CCT .71 / .70 / .67; Wellington .89 / .86 / .83; Serengeti .89 / .86 / .82). The pre-stated expectation held (CP undercovers; betting >= .95). Reading: with site clustering, frame-level exact binomial bounds are not valid and a cluster-level bound is; the cluster bound is 2-10x the truth at 5-20 sites.
C3 (identified-set certificate, band +-.30): 1087 of 1154 pool-rule cases covered (.942, below .95); unshifted pools 978 / 986 (.992); pools with |prior shift| >= .20: 109 / 168 (.65). Cases within a replicate and across replicates (same frames) are dependent. The certificate was not valid under prior shift at this band; no claim that it is calibrated.
C2: 3-5 shifted fold-pools per replicate, almost always Serengeti only (a CCT pool entered in some replicates); mean Q minus R0 = +.276 (replicate range .217-.315), all 20 positive: consistent with Prop C' for label-selected prevalence-shifted pools; not a result on natural shift.
C1: CCT: R0 / Q / Otsu regret .020 / .027 / .315, R0 error .135 vs oracle .115 vs constant-animal .139; Wellington .009 / .008 / .397, .182 vs .173 vs .179; Serengeti .009 / .039 / .009, .060 vs .051 vs .541. In CCT and Wellington R0 is not better than the constant rule (as in 14d); Serengeti is the only informative set.
Not claimed: that Q or the certificate works on camera traps; Tier-1; A*; any novelty. The replicates re-draw site assignment only (same frames, features, probes recipe), so they test split-sensitivity, not new data.
